# hablemos MVP 계획·명세

- 작성일: 2026-11-22
- 상태: 독립 리뷰 3건(sol·opus·neon) 반영본, 사용자 승인 대기
- 저장소: `hablemos` (GitHub Pages로 배포)

## 1. 목표

한국어 화자 입문자가 스페인(카스티야) 스페인어를 짧은 레슨으로 매일 익히는 개인용 웹앱을 만든다. 학습 흐름과 게임화 방식은 듀오링고 같은 앱의 일반적인 장르 관습(유닛 경로, 짧은 문제 묶음, XP·연속 학습·하트, 복습)을 참고하되, 이름·캐릭터·색상·일러스트 등 특정 앱의 브랜드 요소는 쓰지 않는다.

## 2. 확정된 결정

| 항목 | 결정 |
|---|---|
| 형태 | 웹앱 + PWA, 서버 없음 |
| 콘텐츠 | 고정 커리큘럼(저장소 JSON) + Gemini API 보조 |
| AI 역할 | 추가 연습 문장 생성, 대화 연습 |
| API 키 | 사용자가 설정 화면에 입력, 그 브라우저에만 저장, 브라우저에서 Gemini 직접 호출 |
| MVP 기능 | 유닛 경로·레슨, 게임화, 간격 반복 복습, 듣기·말하기 |
| 스페인어 | 스페인 기준(vosotros 포함, 스페인 어휘, es-ES 음성) |
| 설명 언어·대상 | 한국어, 입문(A1) |
| 저장소명 | hablemos |

## 3. 기술 구성

- Vite + React + TypeScript
- PWA: `vite-plugin-pwa`. 빌드 산출물(코드와 커리큘럼 JSON)을 함께 프리캐시하므로 앱 업데이트 때 코드와 콘텐츠가 같이 바뀐다. 런타임 캐시는 설정하지 않아 Gemini 응답은 캐시되지 않는다. 첫 온라인 접속에서 서비스 워커 설치가 끝나면 "오프라인에서도 쓸 수 있습니다"를 한 번 알린다.
- 저장: `localStorage` (§10). 첫 실행 때 `navigator.storage.persist()`를 요청한다.
- 음성: Web Speech API (`speechSynthesis`, `SpeechRecognition`). 음성 인식은 브라우저가 서버로 음성을 보내는 방식이라 오프라인에서는 쓸 수 없다.
- AI: Gemini REST `generateContent`를 `fetch`로 호출하고 구조화 출력(JSON 스키마)을 쓴다. SDK는 추가하지 않는다.
- 테스트: Vitest. 대상은 순수 로직(채점, 말하기 판정, 복습 일정, 스트릭·하트, 레슨 진행, 잠금 해제, 상태 검증, AI 응답 검증)과 커리큘럼 검증(§8).
- 그 외 라우터·상태관리 라이브러리는 추가하지 않는다. 화면 전환은 상위 컴포넌트의 상태 하나로 처리한다.

## 4. 화면

1. 홈(학습 경로): 유닛과 레슨이 위에서 아래로 이어지는 경로. 완료·진행 가능·잠김 상태 표시. 상단에 스트릭, XP, 하트, 복습 대기 수.
2. 레슨: 문제를 하나씩 풀고 '확인'을 누르면 정답·오답 피드백이 하단에 나온다. 피드백에는 정답과 항목의 `note`를 함께 보여 준다. 진행 막대 표시.
3. 레슨 결과: 획득 XP, 정답률, 스트릭 갱신 여부. 하트 소진으로 끝났으면 그 사실과 복습 안내.
4. 복습: §7의 복습 세션.
5. AI 연습·대화 연습: §9.
6. 설정: Gemini API 키 입력·삭제, 모델 ID, 음성 켜기/끄기, 진도 내보내기·가져오기(JSON), 진도 초기화, AI 저장 항목 전체 삭제.

## 5. 문제

### 유형

| 유형 ID | 내용 | 조건 |
|---|---|---|
| `choice_es_ko` | 스페인어를 보고 뜻 고르기(보기 3~4개) | |
| `choice_ko_es` | 한국어를 보고 스페인어 고르기 | |
| `listen_choice` | 듣고 뜻 고르기 | 쓸 수 있는 음성이 있을 때 |
| `assemble` | 한국어를 보고 스페인어 단어 카드로 문장 조립 | 스페인어가 2단어 이상 |
| `translate` | 한국어를 보고 스페인어 입력 | |
| `dictation` | 듣고 스페인어 입력 | 쓸 수 있는 음성이 있을 때 |
| `speak` | 스페인어 문장을 소리 내 읽기 | 음성 인식 지원·온라인·이번 세션에 말하기를 끄지 않았을 때 |

- 직접 입력은 스페인어로만 받는다. 스페인어→한국어는 객관식으로만 묻는다.
- 단어 조립 카드는 정답 문장을 단어로 나눈 것에 다른 학습 항목의 단어 2~3개를 섞는다.
- 입력란과 대화 입력창 아래에 `á é í ó ú ü ñ ¿ ¡` 입력 버튼을 둔다.
- 듣기 문제에는 보통 속도와 느린 속도(0.7배) 재생 버튼을 둔다.
- 보기(오답)는 학습한 항목(완료한 레슨 + 현재 레슨)에서 뽑는다. 정답 항목과 `ko`가 같거나 `es`·`accept_es`가 겹치는 항목은 뺀다. 오답 보기를 2개 이상 만들 수 없으면 그 항목은 다른 유형으로 낸다.

### 채점(입력형)

1. 정규화: 유니코드 NFC, 소문자화, 문장부호(`.,!?¡¿;:"'«»…-`)를 공백으로 바꾼 뒤 연속 공백을 하나로 줄이고 앞뒤 공백 제거
2. 정답(`es`)이나 허용 답안(`accept_es`) 중 하나와 같으면 정답
3. 강세 부호(`á é í ó ú ü`)만 지운 형태가 같으면 정답으로 처리하고 "악센트 확인: café"처럼 정확한 형태를 보여 준다
4. `ñ`는 별개 글자라 `n`과 같게 보지 않는다(`año` ≠ `ano`)
5. 단어 조립은 같은 정규화로 비교한다

### 말하기 판정

- 인식 후보를 최대 3개(`maxAlternatives`) 받아 하나라도 기준을 넘으면 정답
- 정답 문장과 인식 결과를 위 정규화에 강세 제거를 더해 단어로 나누고, 인식 결과의 숫자 0~20은 스페인어 단어로 바꾼다
- 단어 단위 편집 거리(삽입·누락·치환 각 1)가 `floor(0.2 × 정답 단어 수)` 이하이면 정답. 4단어 이하 문장은 전부 맞아야 한다
- 피드백에 인식된 문장을 보여 준다
- 인식 결과가 없거나 오류가 나면 채점하지 않고 '다시 말하기'와 '건너뛰기'를 준다. 권한 거부(`not-allowed`, `service-not-allowed`)면 이번 세션의 말하기 문제를 모두 빼고 이유를 알린다
- '지금은 말할 수 없음'을 누르면 이번 레슨에 남은 말하기 문제를 다른 유형으로 바꾼다

## 6. 레슨 진행과 게임화

### 레슨 구성

- 레슨의 항목마다 한 문제를 낸다. 유형은 그 항목이 지원하고 지금 쓸 수 있는 유형 중에서 무작위로 고른다.
- 순서는 인식형(`choice_*`, `listen_choice`) → `assemble` → 입력형(`translate`, `dictation`, `speak`)으로 정렬한다.
- 처음 틀린 문제는 레슨 끝에 한 번 더 나온다. 다시 나온 문제는 틀려도 더 반복하지 않는다.
- 건너뛴 문제는 정답률과 만점 판정에서 뺀다.
- 레슨 끝에 도달하면 완료다. 하트가 0이 되면 그 자리에서 실패로 끝나고 완료·XP·잠금 해제는 없다.
- 레슨 중간에 나가면 확인을 받는다. 이미 잃은 하트는 돌아오지 않고, 진행은 저장하지 않는다.

### 하트

- 최대 5개. 새 레슨과 완료한 레슨 다시 풀기에서, 처음 나온 문제를 틀릴 때만 1개 준다. 다시 나온 문제, 복습, AI 연습에서는 줄지 않는다.
- 상태는 `{ count, refillStart }`. 5개에서 처음 잃을 때 `refillStart = 지금`으로 둔다.
- 읽을 때마다 `k = floor((지금 − refillStart) / 4시간)`만큼 회복하고 `refillStart += k × 4시간`으로 옮긴다. 5개가 되면 `refillStart = null`.
- 기기 시각이 `refillStart`보다 앞이면 `refillStart = 지금`으로 다시 잡는다.
- 복습 세션을 마치면 1개 회복한다.
- 하트가 0이면 레슨을 시작할 수 없다. 단, 복습 카드가 하나도 없으면(첫 레슨을 아직 못 마친 경우) 하트 제한 없이 레슨을 시작할 수 있다.

### XP

| 활동 | XP |
|---|---|
| 레슨 첫 완료 | 10, 첫 시도 오답이 없으면 +5 |
| 완료한 레슨 다시 완료 | 5 |
| 복습 세션 완료 | 5 |
| AI 연습 | 0 |

### 연속 학습(스트릭)

- 날짜는 기기 현지 시간의 `YYYY-MM-DD` 문자열로 다룬다(UTC 변환 금지).
- 레슨 완료나 복습 세션 완료 때 갱신한다. AI 연습은 세지 않는다.
  - `lastDate`가 오늘이면 그대로
  - 어제면 `count + 1`
  - 비었거나 이틀 이상 전이면 `count = 1`
  - 오늘보다 뒤(기기 시각이 뒤로 감)면 바꾸지 않는다
- 표시할 때 `lastDate`가 이틀 이상 전이면 0으로 보여 준다.

### 잠금 해제

레슨은 순서대로 열린다. 유닛의 마지막 레슨을 마치면 다음 유닛의 첫 레슨이 열린다. 완료한 레슨은 다시 풀 수 있다.

## 7. 간격 반복 복습

- 카드 상태: `{ reps, ease, interval, due }`. `ease` 기본 2.5, 범위 1.3~2.5. `due`는 현지 날짜 문자열.
- 레슨을 완료하면 그 레슨 항목 중 카드가 없는 것만 `reps 0, interval 0, due 내일`로 등록한다. 이미 있는 카드의 일정은 레슨 재완료로 바뀌지 않는다.
- 레슨에서 처음 나온 문제를 틀리면(실패로 끝난 레슨 포함) 그 항목에 오답 규칙을 적용한다. 카드가 없으면 만든 뒤 적용한다.
- 복습 답에 따른 갱신:
  - 정답: `reps + 1`. `interval`은 `reps`가 1이면 1, 2면 3, 그 이후는 `round(interval × ease)`. `ease + 0.1`(상한 2.5). `due = 오늘 + interval`
  - 오답: `reps 0`, `interval 1`, `ease − 0.2`(하한 1.3), `due = 내일`
- 복습 세션: `due ≤ 오늘`인 카드를 `due`가 오래된 순으로 최대 15개 낸다. 문제를 다시 내지 않고, 첫 답으로 카드를 갱신한다. 유형은 레슨과 같은 규칙으로 고른다.
- 복습할 카드가 없으면 '미리 연습'을 준다. `due`가 가까운 카드 최대 10개로 세션을 만들고 카드 일정은 바꾸지 않는다. 마치면 복습 세션처럼 하트 1개와 5 XP를 주고 스트릭을 갱신한다.
- 커리큘럼에서 사라진 항목의 카드는 출제하지 않는다.

## 8. 콘텐츠

### 구조

```
src/content/units.json
Unit   { id, title, description, lessons: Lesson[] }
Lesson { id, title, items: Item[] }
Item   { id, es, ko, accept_es?: string[], types: ExerciseType[], note? }
```

- `note`에는 스페인 특유 표현, 성·관사, ser/estar, 발음(c·z의 [θ]) 같은 메모를 짧게 적는다.
- 한국어 문장 작성 규칙(정답이 하나로 정해지게):
  - 반말은 `tú`, 존댓말은 `usted`로 옮긴다
  - 복수 2인칭은 "(너희)" → `vosotros`, "(여러분, 존댓말)" → `ustedes`처럼 괄호로 단서를 단다
  - 성이 갈리는 문장은 "(여성)"처럼 단서를 단다
  - 그래도 맞는 다른 형태는 `accept_es`에 넣는다
- 커리큘럼 검증 테스트: id 중복 없음, 유형 ID가 유효함, `assemble`은 2단어 이상, 각 유닛에서 객관식 보기를 만들 수 있음

### MVP 분량

4개 유닛 × 3개 레슨 × 레슨당 8~10개 항목(약 110항목)

1. 인사와 소개 (Hola, me llamo…, ¿De dónde eres?)
2. 카페와 음식 (Un café con leche, por favor / zumo, tapas)
3. 가족과 사람 (mi hermano, vosotros 활용 포함)
4. 숫자와 시간 (숫자 1~20, 시각은 1~12시의 en punto·y media·y cuarto·menos cuarto)

콘텐츠는 이번 작업에서 작성한다. 원어민 검수는 하지 않으므로 README에 그 한계를 적는다.

## 9. Gemini 보조

### 공통

- 설정에 키가 없으면 AI 메뉴에는 안내만 보이고 나머지 기능은 그대로 동작한다. 오프라인이면 AI 메뉴를 비활성으로 표시한다.
- 키는 진도 상태와 분리한 `localStorage` 항목(§10)에 저장한다. 설정 화면에 다음을 적는다: 이 브라우저에 저장되며 Gemini로 직접 전송된다, 같은 출처의 다른 페이지 스크립트가 읽을 수 있다, 이 앱 전용 키를 만들어 할당량 제한을 걸어 두기를 권한다. 키 삭제 버튼을 둔다.
- 호출: `POST https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent`, 헤더 `x-goog-api-key`(URL 쿼리에 넣지 않음), `generationConfig.responseMimeType = application/json`과 `responseSchema`
- 키는 오류 메시지·콘솔 로그·내보내기 파일에 넣지 않는다.
- 모델 응답은 텍스트로만 렌더링한다(HTML 삽입 금지).
- 모델 ID는 설정에서 바꿀 수 있다. 기본값은 구현 시점에 공식 모델 목록 문서에서 확인한 안정판 Flash 모델로 정한다.
- 오류를 구분해 한국어로 알린다:

| 경우 | 안내 | 재시도 버튼 |
|---|---|---|
| 401·403 | 키 확인 요청 | 없음 |
| 429 | 할당량 초과, 잠시 후 다시 | 있음 |
| 400 | 모델 ID나 형식 미지원, 설정 확인 | 없음 |
| 5xx·네트워크 오류 | 일시 오류 | 있음 |
| 후보 없음, `finishReason`이 `STOP`이 아님, JSON 파싱·검증 실패 | 응답 형식 오류 | 있음 |

### 추가 연습 생성

- 진입점: 홈에서 완료한 레슨을 눌렀을 때 나오는 'AI 연습' 버튼
- 입력: 그 레슨까지 완료한 레슨들의 `es`를 단어로 나눈 어휘 목록. 그 어휘만 써서 새 문장 8개를 요청한다.
- 모델은 `{ es, ko, accept_es? }`만 만든다. id·유형·출처는 앱이 정한다: `id = ai-<uuid>`, `sourceLessonId`, `types = choice_es_ko, choice_ko_es, assemble, translate`(음성이 있으면 `listen_choice`, `dictation` 추가)
- 검증: 문자열이 비어 있지 않음, `es` 12단어·100자 이하, `ko` 60자 이하, `accept_es` 5개 이하, 기존 항목과 정규화한 `es`가 같으면 버림. 유효 항목이 3개 미만이면 세션을 만들지 않고 알린다.
- 오답 보기는 §5 규칙대로 학습한 항목에서 뽑는다.
- 생성 항목에는 "AI 생성"을 표시한다. 하트·XP·스트릭에 영향이 없다.
- 세션 후 '복습에 저장'을 누르면 `aiItems`에 넣고 카드를 `due 내일`로 만든다. 정규화한 `es`가 이미 저장된 항목은 건너뛴다. 고정 커리큘럼은 바꾸지 않는다.

### 대화 연습

- 상황 3개, 커리큘럼에 맞춤: 자기소개(인사·출신), 카페 주문, 가족 소개
- 시스템 지시: 스페인 스페인어, A1 수준의 짧은 문장, 역할 유지, 사용자 문장에 오류가 있으면 짧게 교정
- 응답 형식: `{ reply_es, reply_ko, correction?: { original, fixed, explanation_ko } }`
- 요청마다 시스템 지시와 최근 12턴만 보낸다. 30턴이 넘으면 새 대화를 권한다.
- 응답은 TTS로 읽을 수 있고, 사용자는 입력하거나 음성 인식으로 말할 수 있다.
- 대화 기록은 메모리에만 두고 저장하지 않는다. 하트·XP·스트릭에 영향이 없다.

## 10. 저장

### localStorage 항목

| 키 | 내용 |
|---|---|
| `hablemos-state` | 진도 상태 JSON |
| `hablemos-gemini-key` | API 키 문자열 |
| `hablemos-backup` | 읽기에 실패한 최근 상태 원문 1개 |

```
State {
  version: 1,
  xp,
  streak: { count, lastDate: string | null },
  hearts: { count, refillStart: number | null },
  completedLessons: string[],
  cards: { [itemId]: { reps, ease, interval, due } },
  aiItems: (Item & { sourceLessonId })[],
  settings: { geminiModel, audio: boolean }
}
```

### 규칙

- 읽기와 가져오기에 같은 검증기를 쓴다(필드 형식, 값 범위, `version`).
- 읽기 실패(형식 오류, 지금보다 높은 `version` 포함): 원문을 `hablemos-backup`에 덮어써 보존하고, 초기 상태로 시작한 뒤 그 사실을 알린다.
- 가져오기 실패: 현재 상태를 그대로 두고 이유를 알린다. 가져오기는 키를 건드리지 않는다.
- 내보내기 파일은 `hablemos-state` 내용만 담는다.
- 저장(`setItem`)이 실패하면 메모리 상태는 유지하고 "저장하지 못했습니다"를 알린다.
- 다른 탭에서 상태가 바뀌면(`storage` 이벤트) 저장된 상태를 다시 읽는다. 진행 중인 레슨은 메모리에만 있어 영향이 없다.
- 진도 초기화는 `hablemos-state`만 지운다. 키는 설정의 키 삭제로만 지운다.
- 이후 스키마를 바꾸면 `version`을 올리고 이전 버전 변환 함수를 추가한다.

## 11. 디자인

- 자체 시각 정체성: 따뜻한 테라코타·올리브 계열 색, 둥근 카드, 큰 터치 영역. 특정 앱의 마스코트·색·글꼴은 쓰지 않는다.
- 모바일 우선(최소 360px 폭), 라이트·다크 모드
- 키보드로 모든 문제를 풀 수 있게 하고(Enter 확인, 숫자 키로 보기 선택), 정답·오답을 색만이 아니라 문구로도 알린다.
- 화면 문구: 합니다체로 통일하고, 오류 문구는 원인과 사용자가 할 일을 함께 쓴다. 구현 후 한국어 UI 문구 점검을 한 번 한다.

## 14. 검증 방법과 한계

- 순수 로직과 커리큘럼은 Vitest로 검증한다.
- 화면은 로컬 개발 서버를 앱 내 브라우저로 열어 확인한다.
- Gemini 실제 호출은 사용자의 실제 API 키가 필요하므로 Claude가 키를 입력하지 않는다. M5 시작 때 사용자가 키를 넣고 짧은 호출 한 번으로 브라우저 직접 호출(CORS)과 구조화 출력이 되는지 확인한다. 그 뒤 구현 검증은 모의 응답으로 한다.
- 음성은 Chrome·Edge(Windows) 기준으로만 확인한다. Android Chrome과 설치형 PWA에서의 듣기·말하기는 배포 후 사용자가 확인한다.

## 15. 남은 결정(구현을 막지 않음)

- 폰 설치: PWA를 폰에 설치하려면 HTTPS로 배포해야 한다. 원격 저장소와 배포 여부는 M6 전에 정한다. 그 전에는 PC 브라우저에서 사용한다.
- 배포 출처: GitHub Pages 프로젝트 페이지(`<계정>.github.io/hablemos`)는 같은 계정의 다른 페이지와 출처가 같아, 그 페이지 스크립트가 저장된 API 키를 읽을 수 있다. 배포한다면 이 앱만 쓰는 출처(별도 도메인이나 전용 호스팅)를 쓰거나 그 위험을 받아들일지 정한다.
