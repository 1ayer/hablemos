# hablemos MVP 계획·명세

- 작성일: 2026-11-22
- 상태: 초안, 사용자 승인 대기
- 저장소: `hablemos` (GitHub Pages로 배포)

## 1. 목표

한국어 화자 입문자가 스페인(카스티야) 스페인어를 짧은 레슨으로 매일 익히는 개인용 웹앱을 만든다. 학습 흐름과 게임화 방식은 듀오링고 같은 앱의 일반적인 장르 관습(유닛 경로, 짧은 문제 묶음, XP·연속 학습·하트, 복습)을 참고하되, 이름·캐릭터·색상·일러스트 등 특정 앱의 브랜드 요소는 쓰지 않는다.

## 2. 확정된 결정

| 항목 | 결정 |
|---|---|
| 형태 | 웹앱 + PWA, 서버 없음 |
| 콘텐츠 | 고정 커리큘럼(저장소 JSON) + Gemini API 보조 |
| AI 역할 | 추가 연습 문장 생성, 대화 연습 |
| API 키 | 사용자가 설정 화면에 입력, 그 브라우저에만 저장, 브라우저에서 Gemini 직접 호출 |
| MVP 기능 | 유닛 경로·레슨, 게임화, 간격 반복 복습, 듣기·말하기 |
| 스페인어 | 스페인 기준(vosotros 포함, 스페인 어휘, es-ES 음성) |
| 설명 언어·대상 | 한국어, 입문(A1) |
| 저장소명 | hablemos |

## 3. 기술 구성

- Vite + React + TypeScript
- PWA: `vite-plugin-pwa` (매니페스트, 서비스 워커로 앱·커리큘럼 오프라인 캐시)
- 저장: `localStorage`에 버전 필드를 둔 단일 JSON 상태. 개인용 데이터량(수백 항목)이면 충분하다. 용량이 문제가 되면 IndexedDB로 옮긴다.
- 음성: Web Speech API (`speechSynthesis` es-ES, `SpeechRecognition` es-ES)
- AI: Gemini REST `generateContent`를 `fetch`로 호출하고 구조화 출력(JSON 스키마)을 쓴다. SDK는 추가하지 않는다.
- 테스트: Vitest (채점, 복습 일정, 스트릭·하트, 잠금 해제, AI 응답 검증 같은 순수 로직)
- 그 외 라우터·상태관리 라이브러리는 추가하지 않는다. 화면 전환은 상위 컴포넌트의 상태 하나로 처리한다.

## 4. 화면

1. 홈(학습 경로): 유닛과 레슨이 위에서 아래로 이어지는 경로. 완료·진행 가능·잠김 상태 표시. 상단에 스트릭, XP, 하트, 복습 대기 수.
2. 레슨: 문제를 하나씩 풀고 '확인'을 누르면 정답·오답 피드백이 하단에 나온다. 진행 막대 표시. 틀린 문제는 레슨 끝에 한 번 더 나온다.
3. 레슨 결과: 획득 XP, 정답률, 스트릭 갱신 여부.
4. 복습: 오늘 복습할 항목으로 만든 세션(최대 15문제).
5. 대화 연습: 상황 선택 후 Gemini와 채팅.
6. 설정: Gemini API 키·모델 ID, 음성 켜기/끄기, 진도 내보내기·가져오기(JSON), 진도 초기화.

## 5. 문제 유형

| 유형 | 내용 | 비고 |
|---|---|---|
| 객관식 | 문장·단어의 뜻을 보기 3~4개 중 선택 | 스페인어→한국어, 한국어→스페인어 |
| 단어 조립 | 단어 카드를 눌러 문장 완성 | 방해 단어 포함 |
| 번역 입력 | 문장을 직접 입력 | 허용 답안 목록과 비교 |
| 받아쓰기 | TTS로 들은 문장을 스페인어로 입력 | 음성 합성이 없으면 건너뜀 |
| 말하기 | 문장을 읽으면 음성 인식 결과와 비교 | 인식 미지원 브라우저(예: Firefox)는 건너뜀, '지금은 말할 수 없음' 버튼 제공 |

### 채점 규칙

- 비교 전 정규화: 소문자화, 앞뒤·중복 공백 제거, 문장부호(`.,!?¡¿;:"`) 제거
- 허용 답안 중 하나와 같으면 정답
- 악센트·`ñ`만 다르면 정답 처리하되 "악센트 확인: café" 같은 안내를 보여 준다
- 말하기는 인식 결과의 단어가 정답 단어의 80% 이상 순서대로 맞으면 정답(정규화·악센트 무시)

## 6. 게임화

- XP: 레슨 완료 10 XP, 실수 없이 완료하면 +5. 복습 세션 완료 5 XP.
- 스트릭: 기기 현지 날짜 기준으로 하루에 레슨이나 복습을 하나 이상 완료하면 이어진다. 하루를 건너뛰면 0으로 돌아간다.
- 하트: 최대 5개. 레슨에서 틀리면 1개 줄고, 4시간마다 1개 회복한다. 0개면 새 레슨은 시작할 수 없고 복습은 할 수 있다. 복습 세션을 완료하면 1개 회복한다.
- 잠금 해제: 레슨은 순서대로 열린다. 유닛의 마지막 레슨을 마치면 다음 유닛이 열린다. 완료한 레슨은 다시 풀 수 있다(XP 획득).

## 7. 간격 반복 복습

- 복습 단위는 문제 항목(문장·단어). 레슨을 완료하면 그 레슨의 항목이 카드로 등록된다.
- SM-2 단순화: 카드마다 `ease`(기본 2.5, 최소 1.3), `interval`(일), `due`(날짜)
  - 정답: interval을 1 → 3 → `interval × ease` 순으로 늘린다
  - 오답: interval을 1로 되돌리고 ease를 0.2 낮춘다
- 레슨에서 틀린 항목은 다음 날 복습 대상이 된다.
- 복습 세션은 due가 오늘 이전인 카드를 오래된 순으로 최대 15개 출제하고, 유형은 항목이 지원하는 것 중에서 고른다.

## 8. 콘텐츠

### 구조

```
src/content/units.json
Unit   { id, title, description, lessons: Lesson[] }
Lesson { id, title, items: Item[] }
Item   { id, es, ko, accept_es?: string[], accept_ko?: string[], words?: string[], types: ExerciseType[], note? }
```

- 문제는 항목(Item)에서 만든다. 오답 보기는 같은 유닛의 다른 항목에서 뽑는다.
- `note`에는 스페인 특유 표현이나 문법 메모를 짧게 적는다(예: "vosotros: 스페인에서 쓰는 '너희'").

### MVP 분량

4개 유닛 × 3개 레슨 × 레슨당 8~10개 항목(약 110항목)

1. 인사와 소개 (Hola, me llamo…, ¿De dónde eres?)
2. 카페와 음식 (Un café con leche, por favor / zumo, tapas)
3. 가족과 사람 (mi hermano, vosotros 활용 포함)
4. 숫자와 시간 (1~20, ¿Qué hora es?)

콘텐츠는 이번 작업에서 작성한다. 원어민 검수는 하지 않으므로 README에 그 한계를 적는다.

## 9. Gemini 보조

### 공통

- 설정에 키가 없으면 AI 메뉴는 비활성 안내만 보이고 나머지 기능은 그대로 동작한다.
- 키는 `localStorage`에만 저장한다. 화면에 "이 브라우저에 저장되며 Gemini로 직접 전송됨"을 표시하고, 로그·내보내기 파일에는 넣지 않는다.
- 요청 헤더 `x-goog-api-key`로 보낸다(URL 쿼리에 넣지 않음).
- 모델 ID는 설정에서 바꿀 수 있다. 기본값은 구현 시점에 공식 모델 목록 문서에서 확인한 안정판 Flash 모델로 정한다.
- 네트워크·할당량·형식 오류는 사용자에게 한국어로 알리고 재시도 버튼을 준다.

### 추가 연습 생성

- 사용자가 완료한 레슨을 하나 고르면, 그 레슨까지 배운 단어 목록을 넣고 새 항목 5~8개를 요청한다.
- 응답은 Item과 같은 형태의 JSON 스키마로 받고, 앱에서 필드·길이·유형을 다시 검증한다. 검증에 실패한 항목은 버린다.
- 생성 항목은 "AI 생성" 표시와 함께 연습 세션으로 바로 풀 수 있고, 저장을 누르면 복습 카드로 등록된다. 고정 커리큘럼은 바꾸지 않는다.

### 대화 연습

- 상황 3개로 시작: 카페 주문, 길 묻기, 호텔 체크인
- 시스템 지시: 스페인 스페인어, A1 수준의 짧은 문장, 역할 유지, 사용자 문장에 오류가 있으면 짧게 교정
- 응답 형식: `{ reply_es, reply_ko, correction?: { original, fixed, explanation_ko } }`
- 응답은 TTS로 읽을 수 있고, 사용자는 입력하거나 음성 인식으로 말할 수 있다.
- 대화 기록은 세션 동안만 메모리에 두고 저장하지 않는다.

## 10. 진도 상태

```
State {
  version: 1,
  xp, streak: { count, lastDate },
  hearts: { count, updatedAt },
  completedLessons: string[],
  cards: { [itemId]: { ease, interval, due } },
  aiItems: Item[],            // 저장한 AI 생성 항목
  settings: { geminiKey?, geminiModel, audio }
}
```

- 읽을 때 형식이 맞지 않으면 기존 값을 `hablemos-backup-<시각>` 키로 보존한 뒤 초기 상태로 시작한다(데이터 손실 방지).
- 내보내기 파일에는 `geminiKey`를 빼고 넣는다.

## 11. 디자인

- 자체 시각 정체성: 따뜻한 테라코타·올리브 계열 색, 둥근 카드, 큰 터치 영역. 특정 앱의 마스코트·색·글꼴은 쓰지 않는다.
- 모바일 우선(최소 360px 폭), 라이트·다크 모드
- 키보드로 모든 문제를 풀 수 있게 하고(Enter 확인, 숫자 키로 보기 선택), 정답·오답을 색만이 아니라 문구로도 알린다.
- 화면 문구는 한국어로 쓰고 `ui-text-ko` 기준으로 점검한다.

## 12. 범위 밖

계정·기기 간 동기화, 리더보드·친구, 푸시 알림, 결제·광고, AI 오답 설명, AI 번역 채점, 다른 언어 과정, 원어민 녹음 음성

## 13. 구현 단계

각 단계는 테스트 통과 후 커밋한다.

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| M1 | 프로젝트 뼈대, 콘텐츠 스키마, 유닛 1~2 콘텐츠, 레슨 엔진(객관식·단어 조립·번역 입력), 채점 | 채점 테스트 통과, 브라우저에서 레슨 1개 완주 |
| M2 | 홈 경로·잠금 해제, XP·스트릭·하트, 결과 화면, 상태 저장·복구 | 로직 테스트 통과, 새로고침 후 진도 유지 |
| M3 | 간격 반복 복습 | 일정 계산 테스트 통과, 날짜를 바꿔 복습 세션 확인 |
| M4 | 받아쓰기·말하기(TTS·음성 인식) | Chrome·Edge에서 동작, 미지원 시 건너뜀 확인 |
| M5 | Gemini 추가 연습·대화 연습, 설정 화면 | 응답 검증 테스트(모의 응답) 통과, 실제 호출은 사용자 키로 확인 |
| M6 | 유닛 3~4 콘텐츠, PWA, 진도 내보내기·가져오기, 화면 문구·접근성 점검 | 빌드 산출물 오프라인 동작, `npm run build` 성공 |

## 14. 검증 방법과 한계

- 순수 로직은 Vitest로 검증한다.
- 화면은 로컬 개발 서버를 앱 내 브라우저로 열어 확인한다.
- Gemini 실제 호출은 사용자의 실제 API 키가 필요하므로 Claude가 키를 입력하지 않는다. 구현 측 검증은 모의 응답으로 하고, 실제 호출은 사용자가 키를 넣고 확인한다.
- 음성 인식은 브라우저·OS에 따라 결과가 다르므로 Chrome·Edge(Windows) 기준으로만 확인한다.

## 15. 남은 결정(구현을 막지 않음)

- 폰 설치: PWA를 폰에 설치하려면 HTTPS로 배포해야 한다(예: GitHub Pages). 원격 저장소와 배포 여부는 M6 전에 정한다. 그 전에는 PC 브라우저에서 사용한다.
